About these measurements

Includes Browsertime, Raptor, Talos, AWSY, mozperftest and Mochitest Speedometer jobs, including comparison browsers, failed runs and retries. Build and queue time are excluded.

Worker-hours sum each run’s wall-clock time within the selected UTC day; parallel runs add together. Runs crossing midnight contribute only their overlap with that day. This measures whole jobs (including setup and cleanup), rather than benchmark timings or CPU time. Pools use the actual Taskcluster provisioner/worker-type IDs. Each row is a performance-test job configuration, with all its runs combined. Search matches job configurations and aggregate names, ignoring case. Totals reflect matching tests. Shares remain relative to all tests in the selected worker pool and project, or all pools when All is selected. Configurations default to descending worker-hours. Click any column header except Activity to sort; click again to reverse. Select All in the Worker pool dropdown to combine matching configurations across pools. Tests are grouped by family. Click a group to expand its full job configurations, sorted within their group using the selected column. Parent rows combine runtime and deduplicate bug IDs; child rows break down the same totals and are not added to them again. Activity shows peak simultaneous running jobs in five-minute buckets over the UTC day. Each row is scaled to its own peak, shown in the Peak running column; hover for bucket counts. The total row combines all configurations. Queue time is not plotted. Previously loaded days are cached in this browser to speed up revisits. A new version of the source data is downloaded again.

Bugs found counts distinct perf-alert bugs created in the past 365 days, using cached mappings and resolutions from STMO query 129802. Like the Performance Regression Tracker, it includes only tests listed in regression tables in each bug’s description, excluding improvement tables and bugs without parsed regressions. Truncated tables are expanded with Treeherder regression alerts where available; otherwise only the tests listed in the description are counted. Reassignment alone cannot include a bug. All bug processing happens in STMO; the browser fetches one cached result. The result refreshes daily at 05:00 UTC, including the tracker’s current job-label cache. Results older than 48 hours are shown as unavailable. Hover for the breakdown, then click a category’s count to open those bugs in Bugzilla. Duplicate is separate from Fixed. The column sorts by total bug count. Its tooltip compares the test’s share of distinct bugs in the selected worker pool and project with its runtime share; a bug linked to several tests counts for each, so bug shares can add up to more than 100%. Job labels use the tracker’s signature cache, with new signatures looked up through their latest jobs within 90 days in the Treeherder database. Tests without a known job label cannot be attributed to this table. Counts describe test history, not historical worker pools. The yearly window does not move with the selected worker date. Group and total rows deduplicate bugs. Zero means no matching bugs were found; “—” means bug data could not be loaded.
